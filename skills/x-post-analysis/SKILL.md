# X 게시글 분석

X 글 하나 또는 여러 개를 읽고 "작성자가 실제로 무엇을 말했고, 왜 썼는지"를 정리할 때 쓴다. 다른 업무(슬랙 제안, 토론, 다이제스트)에 인용하기 **전에** 이 단계를 먼저 거친다.

## Hard rules
1. **전문부터.** 280자 미리보기로 판단하지 않는다. 긴 글(note_tweet) 전문, 인용한 글, 같은 작성자의 스레드 이어짐, 첨부 이미지·영상 설명까지 확인한다.
2. **보이는 것과 추론을 가른다.** 본문·스크린샷에 실제로 나온 동작·수치·대사만 "사실"로 쓴다. 그 사이를 메운 해석은 "추정"으로 표시한다. 추정을 구체 대사나 절차로 키우지 않는다.
3. **의도를 한 문장으로.** 무엇을 알리거나 주장하려는 글인지(제품 공지, 사용 사례 자랑, 의견, 질문, 농담·밈, 투표 등)를 먼저 정한다. 투표·밈·이벤트 글은 기능 평가로 읽지 않는다.
4. **맥락 글 확인.** 인용·답글·직전 며칠의 같은 작성자 글에서 이 글의 전제(연재, 약속, 이벤트 규칙)를 찾는다.
5. **우리 일에 옮길 때는 얇게.** 외부 사례 전체를 이식하지 않고, 가져올 수 있는 조각과 가져오면 안 되는 조각을 나눈다. 원문 의도와 어긋나게 쓰이면 그렇다고 적는다.
6. **읽기 한도를 아낀다.** X 연결은 분당·일일 읽기 한도가 있으니 필요한 필드만 요청하고 같은 글을 반복 조회하지 않는다.

## Steps
1. 글 조회: 본문(긴 글이면 전문), 작성자, 시각, 인용·답글 대상, 첨부 미디어, 공개 지표.
2. 맥락 조회: 인용 글, 작성자의 스레드 이어짐, 필요하면 같은 작성자의 최근 관련 글 몇 개. 투표가 있으면 선택지와 결과.
3. 미디어 확인: 이미지·스크린샷은 내용을 읽고, 영상은 영상 분석으로 넘긴다. 못 본 미디어는 "미확인"으로 둔다.
4. 정리(아래 형식).
5. 다른 산출물에 쓸 때는 "사실" 칸에 있는 내용만 단정형으로 인용한다.

## 출력 형식
- **의도:** 한 문장
- **사실(원문·미디어에서 확인):** 불릿 2~5개, 각 근거 글 링크
- **추정:** 있으면 불릿, 없으면 "없음"
- **맥락:** 이 글이 기대는 전제(연재·이벤트·이전 글)
- **우리에게 옮길 수 있는 조각 / 옮기면 안 되는 조각:** 필요한 경우에만
- **미확인:** 보지 못한 미디어·링크

## Do not
- 미리보기만 보고 요약
- 스크린샷에 없는 절차를 원문 사실처럼 서술
- 투표 결과를 기능 선호 투표로 해석
- 작성자 소속·제품명을 추측해서 붙이기
- 외부 사례를 "우리도 이렇게 하자"로 통째 포장
