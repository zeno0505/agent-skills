# 슬랙 발송 초안

사용자가 **직접** 슬랙에 올릴 초안을 쓸 때 쓴다. 에이전트가 쓸 수 있는 Slack 커넥터의 발송·예약·초안 생성 기능으로 **보내지 않는다**(사용자가 "이 초안을 지금 보내"라고 명시한 경우만 예외). 산출은 채팅에 붙여넣기 가능한 본문이다.

## When to use
- 슬랙 채널·스레드에 올릴 글/답글 초안을 요청할 때
- 스레드 링크·채널을 주고 "맥락에 맞춰", "말투 맞춰", "이어서" 쓰라고 할 때
- 외부 참고(X 글·문서·다른 채널 관행)를 슬랙 제안에 녹일 때

## Hard rules
1. **발송 금지(기본).** 커넥터의 메시지 전송·예약 전송·초안 생성으로 보내지 않는다. 초안 텍스트만 사용자에게 전달한다.
2. **스레드면 먼저 읽기.** permalink 또는 channel+ts가 있으면 부모+답글을 읽은 뒤에만 쓴다. 안 읽고 추측 금지.
3. **말투는 그 자리의 사용자 목소리.** 같은 채널/스레드에서 사용자가 최근에 쓴 글을 샘플로 어미·호칭·길이·목록 습관을 맞춘다. 봇·영문 보고서 톤 금지.
4. **접두어는 맥락 함수.** "그리고/이어서/추가로/한편" 등을 습관적으로 붙이지 말고, 직전 발화가 연타인지·새 안건인지·다른 청중인지에 따라 고른다.
5. **레이어 순서 고정.** 아래 Layer 0→4를 건너뛰지 않는다. 근거 없는 연관·과대 이식 금지.
6. **채널·스레드 밖 사실은 짧게.** 외부 링크는 필요 최소만; "베끼자"가 아니라 "무엇을 가져올지"를 한 줄로.

## Steps

### 1) 스레드·채널 맥락 파악 → 접두어 결정
1. 스레드(또는 채널 최근 메시지)를 읽고 부모 목적, 직전 사용자 발화, 이미 합의된 결정, 열린 질문, @대상(팀/개인)을 적는다.
2. **접두어(Layer 0) 후보를 하나만 고른다.**
   - 직전 본인이 같은 스레드에서 안건을 이어 쓸 때 → `그리고` / `이어서` / `추가로` (직전 문장과 자연스럽게 붙는 것)
   - 새 축·다른 화면으로 넘어갈 때 → `그리고 … 쪽은`처럼 **축을 명시**
   - 다른 청중에게만 보이는 보론일 때 → 직전이 쓰던 "별첨/공유" 틀을 유지
   - 첫 글·스레드 시작이면 접두어 없음(제목/한 줄 목적만)
3. 접두어 결정 이유 한 줄을 초안 위에 *(내부 메모)*로 적었다가, 사용자에게 줄 최종본에서는 뺀다.

### 2) 기존 말투대로 본문을 레이어화
같은 스레드/채널의 사용자 글에서 관찰한 패턴을 복제한다(예: 요/습니다, 불릿, `---` 구분, "의견 있으시면…").

| Layer | 역할 | 쓸 것 | 쓰지 말 것 |
|---|---|---|---|
| **0 접두어** | 직전 발화와의 연결 | 1에서 고른 짧은 연결어+축 | 긴 서론, "안녕하세요" |
| **1 위치** | 이 글이 스레드 목적의 어디에 붙는지 | 단계·화면 이름, "앞 논의와 별개" 같은 범위 한 줄 | 요청 재진술 전체 |
| **2 근거** | 왜 지금 제안인지 | 팀 안의 실제 사례 1~2 + (있으면) 외부 참고의 **얇은** 교훈 | 외부 사례 전체 이식, 과한 프레임 |
| **3 제안** | 팀이 판단할 구체안 | 필드·규칙·1차에서 안 하는 것 | 구현 스펙 장문, 미합의 자동 발송 |
| **4 닫기** | 피드백 요청 | 그 채널에서 쓰던 짧은 청유 | 새로운 CTA 남발 |

작성 순서: Layer 0 → 1 → 2 → 3 → 4. 각 레이어는 짧게; 2와 3이 본문 대부분이다.

### 3) 전달
1. 최종본만 사용자에게 보여 준다(복붙용). 필요하면 "접두어로 ○○를 고른 이유"를 한 줄로만 덧붙인다.
2. 첨부가 필요하면(예: PDF) 본문에 "첨부한 …" 한 줄을 넣고, 무엇을 같이 올려야 하는지 사용자에게 알린다.
3. 발송·예약·커넥터 초안 생성은 하지 않는다.

## Do not
- 스레드를 안 읽고 초안
- 에이전트가 직접 슬랙 전송(명시적 발송 지시 없는 한)
- 외부 글 전체를 "우리 파이프라인"으로 포장
- 스레드에서 이미 합의된 결정과 충돌하는 제안
- 다른 채널 관행을 출처·링크 없이 일반화
