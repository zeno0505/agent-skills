# 한국어 검수

## Overview

문서나 문구를 다른 사람에게 보여주기 전에 **서브에이전트에게 검수시켜**
읽기 나쁜 표현을 찾습니다.

두 가지를 봅니다.

- **문체** — 번역투·상투구·헤징·형식명사처럼 읽기에 나쁜 것
- **전달력** — 그 자리에 없던 사람이 해독할 수 없는 표현

**지적과 대안 문장까지만 내놓고 파일은 고치지 않습니다.**

## When to Use

명시 호출 전용입니다. 사용자가 부르지 않으면 동작하지 않습니다.

- 설계 문서를 팀원에게 공유하기 직전
- UI 카피·공지 문구를 확정하기 직전

**쓰지 말 것:** 맞춤법·오탈자 교정(직접 처리), 번역, 내용을 더하거나 빼는
재작성, AI 생성 여부 판별(에이전트가 쓴 문서라면 답이 정해진
질문입니다).

## 호출

```
/korean-ai-tell-review <파일경로 또는 문구> [프로파일] [독자]
```

**프로파일** — `.md` 파일이면 `설계문서`, 그 외 모든 경우(문구 직접 입력 포함)는
`제품문구` 가 기본입니다. 사용자가 명시하면 그쪽이 우선합니다.

**독자** — `팀내`(기본) 또는 `팀외`. `팀외` 일 때만 K-2 무설명 식별자가
참고에서 확신으로 올라갑니다. 같은 DAG 를 공유하는 팀원에게 `T-042` 는 정상
어휘이고 프로젝트 밖 독자에게는 해독 불가라, 같은 문서의 판정이 독자에 따라
갈립니다.

파일 여러 개면 파일당 하나씩 **최대 4개 동시** 파견합니다. 그보다 많으면
4개씩 나눠 돌리고, **20편을 넘으면 실행 전에 사용자에게 확인합니다**
(노트 폴더를 통째로 가리키면 수십 편이 한꺼번에 잡힙니다).

## 절차

### 1. 계측

```bash
python3 -B ~/.agents/skills/korean-ai-tell-review/scripts/tells.py <경로> --out-dir <스크래치패드>
```

문구를 직접 받았으면 경로 대신 `-` 를 주고 stdin 으로 넘깁니다.

스크립트가 마크다운을 걷어내고 결정적으로 셀 수 있는 신호를 셉니다.
**줄을 지우지 않고 빈 줄로 바꾸므로 줄 번호가 원본과 그대로 맞습니다.**
전처리본은 `--out-dir` 에만 쓰이고 사용자 저장소에는 아무것도 남지 않습니다.

`-B` 는 검수 대상 폴더가 git 으로 관리될 때 `__pycache__` 를 남기지 않기 위한 것입니다.

산출된 `counts` 는 **코드가 센 확정값**입니다. 이후 단계에서 재추측하지 않습니다.

### 2. 파견

`Agent` 도구로 **일반 서브에이전트 1개**를 파견합니다. `fork` 를 쓰지 않습니다 —
맥락을 물려주면 "이 글은 우리가 방금 쓴 것" 이라는 정보가 따라가고, 확증편향으로
없는 티를 만들어냅니다. 누가 썼는지 모르는 편이 판정이 정확합니다.

아래 프롬프트를 채워 보냅니다.

```
당신은 한국어 문서 검수자입니다. 이 글을 누가 썼는지는 알 필요가 없습니다.

카탈로그: ~/.agents/skills/korean-ai-tell-review/references/tells.md   ← 먼저 전부 읽으십시오
도메인 용어: <references/domain-terms.md 의 목록>   ← 면제. 어색한 외래어로 잡지 마십시오
본문: <stripped_path>
계측 결과: <tells.py 가 낸 JSON>   ← 코드가 센 것입니다. 재추측하지 마십시오
프로파일: <설계문서|제품문구>
독자: <팀내|팀외>                  ← 팀외면 K-2 를 확신으로 올립니다

규칙:
- 카탈로그에 없는 항목은 지적하지 마십시오. 직감으로 추가하지 마십시오.
- 지적 전에 그 항목의 캐비엇을 먼저 읽으십시오. 조건을 못 넘기면 지적하지 않습니다.
- 면제 표에 있는 항목은 몇 건이 나오든 지적하지 않습니다.
- 모든 지적에 원문 문장을 그대로 인용하십시오. 요약하거나 고쳐 쓴 인용은 무효입니다.
- 모든 지적에 줄 번호를 다십시오. 계측 결과의 evidence 에 줄 번호가 있습니다.
- 모든 지적에 대안 문장을 쓰십시오. 방향 설명이 아니라 그대로 쓸 수 있는 문장이어야 합니다.
- 대안은 원문의 사실·수치·고유명사를 바꾸지 않습니다.
- 대안은 주장의 강도를 바꾸지 않습니다. 당위를 사실로, 추측을 단정으로 올리지 마십시오.
- 같은 문장을 두 패턴으로 중복 지적하지 마십시오.
- 없으면 "없음" 이라고 쓰십시오. 채우려고 만들지 마십시오.

아래 형식으로만 답하십시오.

## 문체
<줄번호> | <패턴 ID> | <확신|참고> | <원문 인용> | <대안 문장>

## 전달력
<줄번호> | <패턴 ID> | <확신|참고> | <원문 인용> | <대안 문장>

## 총평
<두 줄 이내. 이 글에서 가장 손볼 가치가 있는 것 하나>
```

### 3. 근거 검증

**서브에이전트 보고를 그대로 옮기지 않습니다.** 각 지적의 인용 문자열을
원문에서 직접 찾습니다.

```bash
grep -n "<인용 문자열>" <원본 경로>
```

찾지 못한 항목은 **기각**하고 기각 사유를 보고에 남깁니다. 인용을 원문 그대로
요구한 것이 이 검증을 `grep` 한 번으로 끝내기 위해서입니다.

줄 번호가 어긋난 항목도 기각합니다. 계측기가 줄 번호를 보존하므로 어긋났다면
서브에이전트가 지어낸 것입니다.

### 4. 보고

두 트랙을 분리합니다. 고쳐야 할 이유가 달라서 한 목록에 섞으면 우선순위가
보이지 않습니다.

```
## 문체
| 위치 | 패턴 | 확신도 | 원문 | 대안 |
|---|---|---|---|---|
| :88 | A-7 | 확신 | 확장성을 갖고 있다 | 확장성이 좋다 |

## 전달력
| 위치 | 패턴 | 확신도 | 원문 | 대안 |
|---|---|---|---|---|
| :142 | K-1 | 확신 | 앞서 정한 대로 | T-042에서 정한 잠금 정책대로 |

검증 기각: <N>건 (<사유>)
계측: <N>자 · 이중피동 <N> · 부정대구 <N>(면제) · 연결어미 쉼표 <N>%(면제)
```

`참고` 항목은 표 아래 별도 절에 둡니다. 확신과 섞지 않습니다.

지적이 없으면 **"손볼 곳 없습니다"** 가 정답입니다. 억지 항목을 만들지 않습니다.

### 5. 적용하지 않습니다

사용자가 "적용해줘" 라고 하면 별도 요청으로 받습니다. 이 스킬의 산출물은
보고까지입니다.

## Red Flags — 멈추고 다시 합니다

- 서브에이전트 보고를 확인 없이 옮겼다 → 3단계를 건너뛴 것입니다
- 면제 항목(C-8 부정 대구, C-11 연결어미 쉼표)이 보고에 올라왔다 →
  서브에이전트가 카탈로그의 면제 표를 안 읽은 것입니다. 재파견합니다
- 대안이 원문의 수치·고유명사를 바꿨다 → 검수가 아니라 왜곡입니다
- 대안이 `~해야 한다` 를 `~한다` 로 바꿨다 → 주장의 강도를 바꾼 것입니다
- 지적할 게 없는데 참고 항목으로 채웠다 → "손볼 곳 없습니다" 가 정답입니다
- 계측기가 센 수치를 에이전트 자가 산출값으로 덮어썼다 → 코드가 센 것이 확정값입니다
