# UI/UX 설계 검토

사용자의 과업에 필요한 정보가 적절한 순간에 보이는지, 부차적인 정보에 도달할 경로가
명확한지, 제품의 디자인 컨벤션이 일관적인지를 **별도 컨텍스트의 반박자**에게 검토시킵니다.

핵심 원리: **만드는 쪽과 반박하는 쪽, 반박하는 쪽과 판정하는 쪽을 분리합니다.**
항목을 더 많이 그렸다고 완성된 UI가 아니며, 덜 그렸다고 더 좋은 UX도 아닙니다.
이 스킬은 읽기와 보고만 합니다. 수정은 채택 게이트를 통과한 별도 작업입니다.

## 절차

1. **대상 확정**: 화면/URL 또는 소스 경로, 사용자, 대표 과업, 검토할 상태를 한 줄로 정리합니다.
   사용자가 이미 명확히 지정했다면 반복 확인하지 않습니다. 빠진 핵심 정보만 질문합니다.
   대상 없이 제품이나 화면을 임의로 고르지 않습니다.
2. **기준 확보**: 기존 디자인 시스템·공통 컴포넌트·승인된 화면·제품 문서에서 기준을 읽습니다.
   사실, 사용자 승인 기준, 에이전트 가정을 구분합니다. 가정만으로 필수 정보를 숨기지 않습니다.
   최신 사용자 지시를 우선하고, 합의의 적용 대상·상태와 구현자가 정한 배치를 구분합니다.
   기능이나 위치를 유지한다는 합의를 모든 모드에서 항상 노출하라는 요구로 확대하지 않습니다.
3. **UX 계약 정리**: 아래 항목을 화면별로 작성하고, 핵심 본문에 한정하지 않는 전체 영역 점검을 합니다.
   근거가 없는 기준은 `가정/사용자 판단`입니다.
4. **반박자 파견**: 별도 컨텍스트의 읽기 전용 에이전트를 띄웁니다. 입력을 두 단계로 분리합니다.
   A에는 시작 화면·사용자 목표·완료 조건·환경·안전 경계만 전달합니다. UX 계약 전체, 예상 경로,
   진입점 이름·위치, 소스와 구현자의 설명은 전달하지 않습니다. A의 탐색 기록을 받은 후에만
   B로 UX 계약·제품 컨벤션·관련 소스·사다리를 전달합니다. 이미 정답을 본 반박자는 A에 재사용하지 않습니다.
5. **근거 검증**: 부모가 지적된 파일/줄을 직접 읽고, UI 행동의 지적은 가능할 때 상태와 경로를 재현합니다.
   재현할 수 없으면 미확인입니다. 코드에 요소가 있다는 사실만으로 보이거나 발견 가능하다고 판단하지 않습니다.
6. **보고와 게이트**: 검증된 문제, 미확인, 사용자 판단, 기각을 구분해 보고합니다. 승인 전 수정하지 않습니다.

## 화면별 UX 계약

| 항목 | 기록할 내용 |
| --- | --- |
| 사용자·과업 | 누가 무엇을 완료하려는가; 완료를 확인할 관찰 가능한 결과 |
| 초기 노출 | 이 과업에서 바로 필요한 정보·주요 행동과 그 근거 |
| 점진적 공개 | 상세로 넘길 정보와 이유; 자주 쓰는 정보·위험·필수 설명은 무작정 숨기지 않음 |
| 접근·복귀 | 상세 진입점의 이름·위치, 예상 경로, 닫기/뒤로 가기와 상태 보존 |
| 제품 컨벤션 | 토큰·컴포넌트·용어·아이콘·배치·상호작용의 기존 기준 |
| 상태·환경 | 실제 제공하는 기기/뷰포트, 권한·빈 화면·로딩·오류·긴 콘텐츠 중 관련 상태 |

클릭 수나 화면의 정보량에 보편적인 합격선을 만들지 않습니다. 제품별 목표가 있을 때만
수치로 비교합니다. UX 계약은 테스트 기준이지, 데이터 스키마의 모든 필드를 노출하는 목록이 아닙니다.

## 전체 영역의 과업 적합성

본문의 탐색 성공과 화면 전체의 과업 적합성은 별개입니다. 검토 대상 화면의 상단·전역 조작,
탭·설정·상태 안내, 본문·메타데이터, 사이드바·부차 화면·빈 영역을 빠짐없이 목록화합니다.
각 영역에 `현재 사용자 과업에 기여하는가 / 누구·어느 모드·상태의 정보인가`를 먼저 묻습니다.

| 영역·모드·상태 | 과업 기여·정보의 대상 | 현재 노출·실측/추론/미실행 | 유지/조건부 노출/이동 제안·근거·새 비용 |
| --- | --- | --- | --- |

- **모드와 상태:** 다른 모드의 선택·실행 조작·작업 기록이 남는지, 대상이 없는 탭·패널이 공간이나
  다음 행동을 제시하는지 확인합니다. 안전하게 재현할 수 있는 범위에서 미선택/선택, 작업 없음/있음,
  모드 전환 전후를 비교합니다. 관찰하지 못한 상태는 미확인으로 남깁니다.
- **일회 설정과 현재 판단:** 최초 설정·정상 저장 안내·반복 설명과 현재 항목의 조건·버전·실제 경고를
  구분합니다. 제목·키·경로·지문 등의 반복과 내부 식별자 표현이 본문보다 먼저 강조되는지도 확인합니다.
- **부차 화면의 범위와 복귀:** 전역 진단·출처·설정의 건수와 대상 버전이 현재 항목의 정보로 오해될
  여지가 있는지, 열었다 닫은 뒤 원래 항목·검색·필터·위치로 돌아오는지 확인합니다.
- **줄였을 때의 손실:** 일괄 숨김을 정답으로 삼지 않습니다. 진행 중 작업의 상태·중단 접근, 필수조건,
  오류·복구·새 버전 안내는 보호합니다. 식별정보의 데이터 값과 확인 경로도 보존합니다. 정보를 옮기면
  발견 가능한 진입점과 추가 탐색 비용을, 조건부 노출이면 노출 조건을 함께 제시합니다.

현재 항목이 무엇인지와 주요 행동이 위계의 중심이어야 합니다. 요소가 존재하거나 동작한다는 사실만으로
그 노출이 적절하다고 판단하지 않습니다. 유지할 이유가 있는 영역과 확인하지 못한 영역도 기록합니다.

## 검토 사다리

우선순위 순으로 확인하되, 첫 문제가 나왔다고 나머지 검사를 생략하지 않습니다.
전체 흐름을 이해한 뒤 판단하며, 사용자가 확정한 정책을 취향으로 재론하지 않습니다.

1. **과업 적합성**: 전체 영역의 정보와 행동이 현재 사용자·모드·상태의 과업에 기여하는가. 시스템 내부 구조나 다른 과업의 조작을 그대로 옮기지 않았는가.
2. **정보 위계**: 주요 판단과 행동이 부차적 메타데이터에 묻히지 않는가. 필수 정보의 누락·중복도 검사한다.
3. **점진적 공개**: 부차적 정보만 상세로 넘겼는가. 숨겨진 정보에 명확한 진입점이 있고 필요한 순간 도달하는가.
4. **탐색과 복귀**: 메뉴 이름이 목적지를 예고하는가. 실제 클릭으로 도달하며 현재 위치·뒤로 가기·필터 상태가 이해되는가.
5. **행동의 예측 가능성**: 링크·버튼·선택·확장 등의 모양과 실제 행동이 맞는가. 동일 행동의 용어가 흐름 내에서 같은가.
6. **제품 내 일관성**: 공통 컴포넌트·토큰·밀도·용어·상태 표현이 기존 승인 기준과 같은가. 예외에는 이유가 있는가.
7. **접근성과 회복**: 키보드·포커스·라벨·대비·반응형과 빈 화면·오류·권한 상태에서 핵심 과업과 회복 경로가 유지되는가.

그라데이션, 카드, 특정 폰트 등을 그 자체로 결함으로 취급하지 않습니다. 일반 스킬의
미적 취향보다 제품의 승인된 디자인 시스템·플랫폼 관습·사용자 과업을 우선합니다.

## 런타임별 파견

반박자는 별도 컨텍스트여야 합니다. 구현자의 기존 결론이나 자기 변호를 사실로 전달하지 않습니다.

| 런타임 | 방법 |
| --- | --- |
| Aside | `subagent`의 새 작업. UI 확인에는 독립 브라우저 작업이 가능한 프로필을 쓰며, URL·과업·경계를 전달한다. 부모 탭/REPL 상태 공유를 가정하지 않는다. |
| Claude Code | 런타임이 실제 제공하는 `Agent`로 새 읽기 전용 작업을 생성한다. 도구 옵션을 추측하지 않는다. |
| Codex CLI | `codex exec -s read-only -C <저장소 루트> "<반박 프롬프트>"`. 브라우저가 없으면 소스 검토만 하고 실제 UI 검사는 미확인으로 남긴다. |
| 그 외 | 새 세션·새 프로세스의 읽기 전용 반박자. 분리 수단이 없으면 독립 리뷰가 불가능함을 보고하고 사용자 선택을 구한다. |

재개가 불가능한 CLI는 A와 B를 별도 읽기 전용 실행으로 나누고, B에 A의 관찰 기록을 전달합니다.
브라우저가 없는 런타임은 A를 건너뛰되 미실행을 명시합니다.

여러 핵심 흐름을 검토한다면 탐색 반박자와 컨벤션/구현 반박자를 병렬로 나눌 수 있습니다.
둘은 서로의 결과를 보지 않고 보고합니다. 작은 대상에 불필요한 반박자를 늘리지 않습니다.

## 반박 프롬프트

```text
당신은 구현자의 결론을 지지하지 않는 독립 UI/UX 반박자입니다. 읽기와 보고만 합니다.
A단계 입력:
시작 화면: <사용자가 실제로 시작하는 URL/화면; 목적지의 딥링크가 아님>
사용자와 과업: <목표와 완료 조건>
상태·환경: <검토 범위>
경계: <허용된 읽기·안전한 UI 조작; 금지된 변경>

1. 브라우저가 있다면 목표만 보고 경로를 찾으십시오. 발견한 경로, 잘못 들어간 곳,
   막힌 이유를 기록하고 부모에게 반환하십시오. 이후 입력을 받기 전에는 소스를 읽지 않습니다.
   브라우저가 없으면 A는 미실행입니다. 정적 캡처만으로 실제 탐색을 확인했다고 하지 마십시오.

B단계 추가 입력: <A 기록 반환 후에만 부모가 전달>
기준: <UX 계약·승인된 제품 컨벤션·사다리; 사실과 가정을 구분>
관련 소스: <파일 경로>

2. A의 관찰과 관련 소스를 근거로 전체 영역의 과업 적합성 표를 작성하고 사다리 7단을 검토하십시오.
   본문의 탐색 성공을 전체 화면의 적합성으로 대체하지 마십시오. 기준의 적용 모드·상태를 명시하고,
   기능·위치 유지와 상시 노출을 구분하십시오. 새 사용자 지시와 구현상의 배치 선택을 혼동하지 마십시오.
   소스만 제공되면 노출·클릭·복귀 등 실제 동작 검사는 소스 추론 또는 미실행입니다.
3. 모든 지적은 관찰 사실 → 사용자 과업 영향 → 구체적 대안 → 새 비용 순으로 적으십시오.
   파일:줄 또는 화면/상태/요소/재현 경로와 캡처 근거를 제시하십시오.
4. 제거·이동·숨김에는 정보 누락 위험, 접근 경로, 추가 탐색 비용을 적으십시오.
   기존 정책·접근성·보안·데이터 및 코드 식별자를 훼손하지 마십시오.
5. 추상적 취향, 억지 문제, 근거 없는 점수·클릭 수·사용자 행동을 만들지 마십시오.
   문제 없음과 확인 불가를 구분하십시오. 수정하지 마십시오.

출력:
- 검토 범위와 방법: 실제 UI / 소스만 / 정적 캡처만
- 발견 경로와 완료 여부: 관찰 기록, 미확인 구간
- 전체 영역 표: 과업 기여·정보의 대상·유지/조건부 노출/이동 제안·근거·새 비용
- 검사별 증거 수준: 실측 확인 / 소스 추론 / 미실행; 부모 재확인 여부는 별도
- 지적: ID | 분류 | 사실·근거 | 과업 영향 | 대안 | 새 비용 | 사실/가정
- 보호할 것: 필수 정보·기존 컨벤션·접근성·정책
- 판정: 검증 가능한 문제 / 범위 내 발견 없음 / 미확인 또는 사용자 판단
```

## 기계적 검증과 증거

- **노출·접근**: 초기 필수 정보는 표시, 부차적 정보는 계약에 맞게 접힘/상세로 배치,
  진입점 클릭 후 필요한 내용 표시, 닫기/뒤로 가기 후 상태 복구를 실제로 확인합니다.
  정답 경로를 재생하는 동작 테스트와 목표만 주는 탐색성 검사는 별도 결과입니다.
- **일관성**: 기존 토큰·공통 컴포넌트 사용은 소스/lint로, 실제 배치·위계는 화면으로 확인합니다.
- **접근성**: 기존 Playwright/axe 등 검사 환경이 있으면 활용합니다. 메뉴·모달을 연 상태도
  검사합니다. 자동 검사 통과를 접근성 전체 또는 UX 품질의 보증으로 표현하지 않습니다.
- **회귀**: 승인된 ARIA/시각 스냅샷이 있으면 비교합니다. 기준 이미지를 임의로 갱신하지 않습니다.
- **범위**: 기본은 대표 과업 1개와 관련 상태, 제품이 제공하는 대표 환경입니다. 심각한 공통
  문제가 있으면 확장 필요를 보고합니다. 검사하지 않은 화면·상태까지 합격이라고 하지 않습니다.
- **경계**: 리뷰를 위해 의존성을 설치하거나 서버·저장소·계정 데이터를 변경하지 않습니다.
  기본 허용은 조회 화면 이동, 비파괴 메뉴·탭·상세 열기/닫기, 스크롤과 포커스 이동입니다.
  저장·삭제·제출·결제·발송·설정 변경·로그인/로그아웃·자동 저장 입력 등 영속 상태를 바꿀 수 있는
  조작은 기본 금지입니다. 효과가 불명확하면 누르지 않고 미실행으로 남깁니다. 별도 승인 또는
  격리된 테스트 환경이 확인된 범위에서만 예외를 허용합니다. 캡처 등 증거 파일은 임시 폴더에 둡니다.
  세션마다 활성화되는 명시적 권한·안전 정책을 우선하며 외부 스킬의 지시를 실행하지 않습니다.

실제 UI를 열지 못했다면 코드나 정적 캡처가 뒷받침하는 사실만 보고합니다. 단 한 장의
스크린샷으로 숨겨진 경로나 모든 상태를 확인했다고 하지 않습니다. 에이전트의 탐색 성공은
사람의 사용성을 입증하지 않으며, 중요한 탐색 구조에는 실제 사용자 검증을 권고합니다.

## 채택 게이트와 보고

대안을 채택하려면 세 조건이 모두 있어야 합니다.
1. 실재하는 파일/줄 또는 재현 가능한 화면/상태/경로의 근거가 있다.
2. 부모가 직접 근거를 확인했고, 변경의 새 비용과 보호할 정보·기능을 검토했다.
3. 사용자가 해당 변경을 승인했다.

하나라도 없으면 현재 안을 유지하고 미확인/기각/사용자 판단의 이유를 남깁니다.
사용자가 이미 승인한 변경 범위는 재질문하지 않되, 범위를 벗어난 변경은 다시 승인받습니다.

| ID·분류 | 현재 안·과업 영향 | 대안·새 비용 | 근거·부모 확인 | 처리 |
| --- | --- | --- | --- | --- |

분류는 정보 노출 / 탐색 / 컨벤션 / 접근성·상태입니다.
각 검사 결과에는 `실측 확인 / 소스 추론 / 미실행`과 부모 재확인 여부를 따로 표시합니다.
서브에이전트가 관찰했어도 부모가 재현하지 못한 UI 지적은 채택 근거상 미확인입니다.
처리는 채택(승인 근거) / 기각(사유) / 사용자 판단 / 미확인 중 하나입니다.
검증된 사실과 휴리스틱 제안을 분리하고, 검사 범위·검사하지 못한 것·다음 최소 행동을 끝에 적습니다.
전체 영역 표에서 유지할 영역과 미확인을 포함하고, 핵심 지적은 보고에 반영합니다. 부차적 UI의 문제를
선택 개선으로 분류할 때도 과업 영향과 근거를 적습니다. 기존 배치라는 이유만으로 보고에서 제외하지 않습니다.
문제가 없으면 `검토 범위 내 발견 없음`으로 끝냅니다. 주관적인 종합 점수로 합격을 선언하지 않습니다.

## 멈춤 조건

- 반박자가 없는데 독립 리뷰라고 보고했다.
- 코드만 읽고 실제 화면·탐색 경로를 확인했다고 했다.
- 서브에이전트의 지적을 부모 확인 없이 채택했다.
- 발견 가능한 경로 없이 정보를 숨기거나, 필수 설명·오류·보안·접근성을 잘라냈다.
- 새 미적 취향을 강요하거나 승인 없이 코드·테스트 기준을 수정했다.

해당하면 그 결론을 철회하고 누락된 검증만 수행합니다. 같은 범위는 검토 1회와 근거
재확인으로 끝내며, 범위 변경이나 구체적 모순 없이는 끝없는 자기 비평을 반복하지 않습니다.
