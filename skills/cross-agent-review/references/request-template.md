# 검증 요청 문안 템플릿

`orca terminal send --terminal <상대핸들> --text "..." --enter --json` 으로 보낸다.
길면 파일로 쓰고 경로만 전달한다.

아래 일곱 요소는 **하나도 빼지 않는다.** 빠진 만큼 왕복이 낭비된다.

---

## 템플릿

```text
[주제]에 대한 검증을 요청합니다. 요청서를 [경로]에 커밋했습니다 (커밋 [해시]).

배경입니다.
[왜 이 결정이 필요한지, 어떤 제약이 이미 확정됐는지]

검증 대상은 [항목 목록]입니다. [가장 중요한 항목]이 최우선입니다.
[그것이 왜 최우선인지 — 무엇이 무너지는지]

중요한 부탁이 셋 있습니다.

첫째, 무비판적 동의 금지입니다. 이 요청서는 제가 작성했고 [어느 쪽]으로
기울어 있습니다. 그 편향을 의심해 주십시오. 반대 근거가 있으면 반드시
명시해 주십시오.

둘째, 확인하지 못한 것은 확인 실패로 명시해 주십시오. 추정을 사실처럼
쓰지 마십시오. 가능하면 공식 문서를 브라우저로 직접 열어 확인하고 출처
URL을 붙여 주십시오. agent-browser CLI가 설치되어 있습니다. 헤드리스가
403이면 --headed 플래그를 붙이면 됩니다.

셋째, 작업을 마치면 반드시 마지막에 아래 명령으로 저에게 알려 주십시오.
제 터미널 핸들은 [내 핸들] 입니다.

orca terminal send --terminal [내 핸들] --text "작업 완료. 결과 경로와 3문장 요약" --enter --json

이 호출은 매 작업의 마지막 단계로 고정해 주십시오.

응답은 [결과 경로]에 저장해 주시고, 저장소 문서와 코드는 수정하지 말아
주십시오. 의존성 변경이나 파일 이동도 하지 마십시오. 이 단계는 검증이고
[사용자가 결정할 항목]은 사용자가 정합니다. 확정하지 마십시오.
```

---

## 반박을 보낼 때 추가할 것

2회차에는 위에 더해 이렇게 시작한다.

```text
검증 잘 받았습니다. 재검토 의견을 [경로]에 작성했습니다.

수용한 것은 [n]개입니다. [각각 한 줄로. 내가 무엇을 틀렸는지 명시]

반박은 [n]개입니다.

[항목 ID] [주장]. [직접 확인한 근거 — 파일 경로, 코드 인용, URL].
[상대 문서 내부의 불일치가 있으면 그것을 지목]

무비판적 동의는 하지 말아 주십시오. 제 반박이 틀렸으면 근거를 들어
반박해 주십시오.
```

---

## 자주 빠지는 것

| 빠뜨리는 것 | 결과 |
| --- | --- |
| 콜백 명령 | 상대가 끝내고도 알리지 않아 사용자가 수동 확인 |
| 내 편향 고지 | 상대가 내 결론을 강화하는 근거만 찾아옴 |
| 확인 실패 명시 요구 | 추정이 사실로 섞여 들어옴 |
| 저장소 수정 금지 | 검증 대상이 검증 중에 바뀜 |
| 사용자 결정 항목 표시 | 에이전트가 정책을 대신 확정 |
