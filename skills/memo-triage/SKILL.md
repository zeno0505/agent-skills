# 메모 처리

사용자가 하던 일을 끊지 않고 떠오른 생각을 남기면, 그 생각이 **실행으로 이어지게** 한다. 기록에서 끝내지 않는다: 의견과 실행안을 붙이고, 승인되면 실행하고, 결과를 남긴다.

## Inputs (런타임 지침에서 받는다 — 스킬 본문에 하드코딩하지 않는다)
- 메모 DB 위치와 스키마(아래 「DB 스키마」와 같은 속성 이름)
- 포착 경로 값(대화로 받으면 실행 주체 이름, 개인 채팅에서 가져오면 그 경로 이름)
- 리마인드를 보낼 사용자 본인 채팅 채널
- 업무 맥락을 찾아볼 곳(슬랙, 문서 도구 등)
- 실행 권한(무엇을 바로 하고 무엇을 승인받는지)

## DB 스키마
`제목`(title) · `상태`(포착 / 의견 완료 / 실행 대기 / 실행 중 / 완료 / 보류 / 버림) · `분류`(업무 / 기술) · `알림 시각`(date, 시간 포함) · `알림 보냄`(checkbox) · `포착 경로`(select) · `원문 링크`(url) · `실행 결과`(url) · `처리한 에이전트`(text)

본문 구조: `## 원문` → `## 의견` → `## 실행 기록`. 원문은 받은 그대로 두고 고치지 않는다.

## Hard rules
1. **쓰기 규칙.** 수정 직전에 다시 읽는다. 본문은 덮어쓰지 않고 아래에 덧붙인다. 덧붙인 내용마다 날짜와 실행 주체를 적는다.
2. **원문 보존.** 사용자 문장을 요약·교정하지 않고 `## 원문`에 그대로 둔다.
3. **중복 수집 금지.** 개인 채팅에서 가져올 때는 사용자가 쓴 메시지만 가져온다. 커넥터가 사용자 계정으로 보내면 작성자로는 구분되지 않으므로, 에이전트가 이 채팅에 보내는 메시지는 **항상 `🔔`(리마인드) 또는 `🤖`(질문·보고)로 시작**하고, 수집할 때 이 두 접두어로 시작하는 메시지는 건너뛴다. `원문 링크`가 이미 DB에 있는 메시지도 건너뛴다.
4. **리마인드는 한 번만.** 보내기 직전에 행을 다시 읽어 `알림 보냄`이 꺼져 있을 때만 보낸다. 보낸 직후 `알림 보냄`을 켠다.
5. **실행 권한을 넘지 않는다.** 남에게 보이는 일은 실행안까지만 쓰고 승인을 기다린다.
6. **추측을 사실처럼 쓰지 않는다.** 업무 맥락은 찾은 출처 링크를 붙이고, 못 찾았으면 못 찾았다고 쓴다. 기술 의견은 근거와 확신 정도를 함께 쓴다.

## Steps

### 1) 포착
1. 메모 DB에 행을 만든다: `제목`(한 줄 요약), `상태 = 포착`, `포착 경로`, `원문 링크`(있으면), `처리한 에이전트`.
2. `## 원문`에 사용자 문장을 그대로 적는다.
3. 리마인드 요청이 있으면 `알림 시각`을 정한다.
   - 시각이 명시되면 그대로 쓴다(KST).
   - 「아침」은 08:30, 「점심」은 13:00, 「저녁」·「퇴근 전」은 18:00으로 본다.
   - 「내일 아침」: 00:00~05:59에 받았으면 **그날** 08:30, 06:00 이후면 다음 날 08:30.
   - 해석한 시각을 `## 원문` 바로 아래에 한 줄로 적는다(예: `알림 시각 해석: 2026-10-15 08:30 KST (「내일 아침」)`).

### 2) 의견
1. `분류`를 정한다.
   - **업무:** 사람·일정·결정·회사 일에 관한 것. 슬랙·문서 도구에서 관련 대화와 문서를 찾아 **알고 있는 맥락**을 덧붙인다. 각 항목에 출처 링크.
   - **기술:** 설계·도구·코드·방법에 관한 것. 근거(문서, 코드, 경험적 사실)를 들어 **에이전트 자신의 의견**을 덧붙인다. 확신이 낮으면 그렇다고 쓴다.
   - 둘 다 해당하면 주된 쪽으로 분류하고 다른 쪽 내용도 함께 쓴다.
2. 의견 끝에 **실행안**을 쓴다: 「실행한다면 이렇게」— 무엇을, 어떤 결과물로, 바로 할 수 있는지 승인이 필요한지.
3. `## 의견`에 덧붙이고 `상태 = 의견 완료`로 바꾼다. 대화 중이면 의견과 실행안을 사용자에게도 짧게 보여 준다.

### 3) 결정과 실행
1. 실행안이 **바로 할 수 있는 일**이면 실행하고 `상태 = 실행 중` → 끝나면 `완료`.
2. 승인이 필요한 일이면 `상태 = 실행 대기`로 두고 사용자에게 묻는다. 승인되면 `실행 중`으로 바꾸고 실행한다. 보류·버림이면 그대로 바꾼다.
3. 진행 중에 멈춰야 하면(한도, 세션 종료) `## 실행 기록`에 지금까지 한 일과 다음 행동을 덧붙인다. 다른 실행 주체가 그 기록만 보고 이어서 할 수 있어야 한다.
4. 결과물 링크를 `실행 결과`에 넣는다.

### 4) 리마인드 발송 (루틴에서)
1. `알림 시각 <= 지금` 이고 `알림 보냄 = 꺼짐`인 행을 알림 시각 순으로 조회한다.
2. 행마다 다시 읽어 `알림 보냄`이 여전히 꺼져 있는지 확인한다.
3. 사용자 본인 채팅으로 보낸다. 형식: 첫 줄에 `🔔 리마인드:` + 제목, 다음 줄에 의견 한두 줄 요약, 마지막 줄에 메모 페이지 링크.
4. 바로 `알림 보냄`을 켠다.

### 5) 수집 (루틴에서)
1. 사용자 본인 채팅에서 마지막 수집 이후의 메시지를 읽는다. 마지막 수집 시점은 `포착 경로 = 개인 채팅 경로`인 행 중 가장 최근 `원문 링크`의 메시지 시각으로 정한다. 그런 행이 없으면 최근 7일을 읽는다.
2. Hard rule 3에 따라 걸러 낸 메시지마다 1)~2)를 수행한다.

## Out of scope
- 메모 DB를 만들거나 스키마를 바꾸는 일
- 일정을 정하는 일(루틴이 정한다)
- 남에게 보이는 실행을 승인 없이 하는 일
